# Learning Record 格式

Learning record 放在 `./learning-records/`，顺序编号：`0001-slug.md`、`0002-slug.md`。目录按需创建：写第一条时才建。

它们是教学领域的 ADR（架构决策记录）：记录不显然的收获、关键洞察、以及用户自述的基础，用来校准后续课程。它们是计算最近发展区的依据。

这个目录在工作区根目录，在 `docs/` 之外，所以不参与站点构建。learning record 是决策级状态，不是课程内容，永远不出现在侧边栏与搜索里。

## 模板

```md
# {学到了什么 / 确立了什么的短标题}

{1-3 句：学到了什么（或确立了怎样的原有基础），以及对后续课程意味着什么。}
```

就这么多。一条记录可以只有一个段落。价值在于记录**「这件事现在算会了」以及「它如何改变下一步教什么」**，不是把各节填满。

## 可选章节

只在真能增加信息时使用。多数记录不需要。

- **状态** frontmatter（`active | superseded by LR-NNNN`）：当早先的理解被推翻并替换时用。
- **证据**：用户是怎么证明理解了的——具体到**哪一课的哪一道题答对了、哪个练习完成了、引用了他什么经历**。写成「第 3 课的 Quiz 一次答对」「自己改出了 /about 路由」这种可回溯的事实，不要写「他好像懂了」。这条会在未来被重新审视时救你。
- **影响**：为后续课程解锁了什么、排除了什么。不显然时才写。

## 编号

扫 `./learning-records/` 里最大的编号，加一。

## 什么时候写

满足任意一条就写：

1. **用户对某个不平凡的东西展现了真实理解**：不是接触过，而是能正确使用。这会抬高下一课的地板。
2. **用户自述了原有基础**：「这个我早会了。」记下来，包括他自己声称的深度，避免以后重教。
3. **纠正了一个误解**：他原本理解错了，现在明白为什么错。价值极高——这类记录能预测未来的绊脚石。
4. **mission 因学习而转向**：他发现自己真正在意的是别的东西。更新 `MISSION.md` 并交叉链接。

### 什么不算

- **只是「讲过了」的材料。** 覆盖不等于学习，等证据。
- **已经压缩进 `GLOSSARY.md` 的术语定义。** 不要重复。
- **逐次会话的活动日志。** learning record 不是日记，是决策级洞察。

## 取代关系

后来的记录推翻早先的时，把旧记录标成 `状态: superseded by LR-NNNN`，不要删除。理解如何演变本身就是有用的信号。
